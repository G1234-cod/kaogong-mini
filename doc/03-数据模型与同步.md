## Transport 抽象（同签名双实现）

`src/services/request.ts` 定义接口，`getTransport()` 按环境返回实现（两者签名完全一致，切换零改动）：

```ts
interface Transport {
  login(code: string): Promise<AuthInfo>          // stub: 本地伪 openid；http: POST /auth/login
  getSnapshot(): Promise<Partial<AppData> | null>  // stub: 读 storage；http: GET /data/snapshot
  writeOps(ops: WriteOp[]): Promise<void>          // stub: 写 storage(80~200ms 假延迟)；http: PUT /data/keys
  getRewards(): Promise<GrantItem[]>               // stub: []；http: GET /rewards（任务定义）
  getGrants(): Promise<GrantItem[]>                // stub: []；http: GET /grants（发放券）
}
```

- `storageTransport.ts`：本地 stub。80~200ms 人为随机延迟模拟真实网络，**刻意避免"同步假象"掩盖异步 bug**（设计决策）；按 role 选命名空间实现 guest 沙盒
- `httpTransport.ts`：真实后端（`Taro.request`，BASE_URL 环境变量）。上线前双轨开关切换

## 启动与写入流程

**启动（app.ts onLaunch → store.bootstrap()）**：

```
读 kg-auth 缓存 token ─无效─→ Taro.login → auth.login(code) → 存 kg-auth
        │有效
        ▼
flushWriteQueue()  # 重放上次断网期间的失败写操作（kg-write-queue）
        ▼
fetchSnapshot()
  ├─ user   → snap 非空 → normalize.mergeWithDefaults(snap) → hydrate
  │           snap 为空 → 转正上传检测（见 02）→ DEFAULTS
  └─ guest  → buildGuestData() 演示数据（不请求服务端数据）
        ▼
ready = true → 渲染页面（沿用 loading-page 全屏骨架）
```

**写入（useData().set(key, value) 对外签名与旧版一致）**：

```
set(key, value)
  → setState 乐观更新（页面立即反馈）
  → writeOps([op(key, value)])
      ├─ 成功 → 完成
      └─ 失败 → 入 kg-write-queue（tries+1）→ 下次启动 flush 重放（退避重试）
```

stub 阶段"本地写不会失败"，队列机制在 httpTransport 联调后才真正接受考验——**离线模式（开发者工具 Offline）页面不白屏、写操作不报错、恢复联网后数据补传**是验收硬标准。

## 服务端表结构（SQLite，SQLAlchemy models.py）

现有 4 张 + 任务体系 1 张新表（详见 [05](./05-任务与奖励体系.md)）：

```python
users:        openid(pk) / role('user'|'guest') / nickname / last_seen_at(待加) / created_at
user_data:    openid+key(pk) / value(JSON文本) / ts      # AppData 18 域逐域一行
tasks:        id(pk) / title / emoji / description
              cond_type / cond_param / mode / hidden
              scope('all'|'users') / target_openids(JSON数组)
              active / created_at                        # B 端发布的任务定义（待建，见05）
rewards:      id(pk) / title / emoji / description      # 旧奖池表（演进为 tasks 后废弃）
grants:       id(pk) / openid(index) / title / emoji / description / granted_at(index)  # B端直接发的券
```

**DATABASE_URL 环境变量切换 sqlite/mysql，零代码改动**（已定 SQLite：备份 = 拷文件，1000 用户 ≈ 1GB 无压力）。

## 合并与迁移（store/normalize.ts）

沿用旧版 `mergeWithDefaults` 语义，服务端字段演进兼容层：

1. 逐 key 取 snapshot 值，缺省用 DEFAULTS
2. 迁移规则沿用旧版：foods 旧 string[] → FoodItem[]、LedgerEntry 补 type、Note 补复习字段、rewards 逐条补新字段（`condType/condParam/scope` 缺省补默认）、settings 深合并（city 缺省许昌）
3. 新增字段标准流程：`types/index.ts` 加类型 → DEFAULTS 加默认 → normalize 写迁移 → 页面直接用

## 数据量与安全

- 估算：1 用户全量数据 ≈ 1MB/年（打卡/笔记/账本/番茄合计）；服务器存储为硬盘占用而非内存，读时临时展开，50 人同时在线仅几十 MB 内存
- 每日自动备份见 [08](./08-部署与运维.md)（cron 拷 `.db` 文件）
- 传输安全：全站 HTTPS（request 合法域名要求）；鉴权 Bearer token；管理接口独立 X-Admin-Token
