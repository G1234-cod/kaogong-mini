# 01 · 项目总览

## 产品定位

**考公小助手**由旧版单用户 PWA（`e:\project\app`，给一位河南备考学生定制的日常生活管家）演进为**多用户微信小程序三端体系**，定位从"私人定制"扩展为"小圈子备考激励工具"：

- **C 端（小程序）**：考公学生（主理人自己 + 亲友，约 5 人起步）日常使用——倒计时督促、打卡、奖励激励、生活管理，全部功能与旧 PWA 对齐
- **B 端（管理后台）**：主理人专属——看用户统计、发布任务、发奖励券，替代旧 PWA 的"看板端（Observer）"角色
- **后端（FastAPI）**：账号判定、数据上云、外部服务代理（天气/AI/一言）、任务与发放的中枢

产品本质延续旧版：**不是题库或知识学习工具，而是围绕备考生活的"督促 + 激励 + 事务"管家**。激励机制（任务 → 达成 → 奖券）是核心卖点，也是 B 端存在的主要理由。

## 三端架构

```
┌─ C 端 小程序（Taro 4 + React）────┐      ┌─ 后端 FastAPI + SQLite ──────────┐      ┌─ B 端 Vue 3（静态托管）─┐
│ 首次打开：试玩 / 正式开始 二选一    │ HTTP │  /auth/login   静默登录+建档       │      │  看板（统计图表）        │
│ 正式用户：数据全量上云（乐观更新）  │◄────►│  /data/*       AppData 18 域同步   │◄────►│  用户列表/详情（全明细） │
│ 游客：本地沙盒，转正时打包上传      │      │  /tasks        任务定义（拉取合并） │      │  任务发布/发券           │
│ 唤起美团外卖：navigateToMiniProgram│      │  /proxy/*      天气/AI/一言 代理    │      │  备份/数据导入           │
└───────────────────────────────────┘      │  /admin/*      X-Admin-Token 保护  │      └────────────────────────┘
                                            │  API Key 全部仅存后端 env        │
                                            └──────────────────────────────────┘
```

## 用户与角色

| 角色 | 来源 | 数据 | 权限 |
|------|------|------|------|
| 正式用户（user） | 首次打开选"正式开始"，微信静默注册 | 全量上云（`user_data` 表） | 全部功能 |
| 游客（guest） | 首次打开选"试玩看看" | 本地沙盒（storage `kg-guest-data`），服务器只记一条身份（users 表 role=guest）+ last_seen | 试玩演示数据；可随时在设置页升级为正式用户 |
| 管理员（主理人） | B 端输入 ADMIN_TOKEN | — | B 端全部能力：看全部用户全部数据、发任务、发券 |

账号 = 微信 openid。**没有白名单**（旧方案已废弃）：任何人可注册，陌生访客走游客通道体验后自选是否注册。面试官/陌生微信打开即游客，看到完整的演示闭环。

## 设计原则底线（长期遵守）

延续旧版（历史决策，勿推翻）：

1. **提醒以页面内呈现为主**：卡片高亮、弹窗、Toast，到点提醒依赖用户打开小程序；例外：用户可在设置 → 服务通知**主动开通**微信订阅消息（授权累积额度），每天 7:30 推送到期待办/待复习闪卡/重要日期（游客不推送），详见 [04](./04-功能说明.md)
2. **任务/奖励发放权在 B 端**：用户端任务与奖池只读展示（含预设池），用户不能自定义任务（旧版 PWA 明确要求，延续）
3. **文案一律研友/朋友口吻**，不得出现恋爱/暧昧语句（用户明确要求）
4. **不要深色模式**：白卡片 + 靛蓝主色（#4f46e5）+ 圆角 14px；状态色只有红（危险/超支/落后）、橙（提醒）、绿（成功）
5. **自研 DatePicker，禁原生日期控件**（旧版 Windows 缩放模糊教训）；时间选择可用小程序原生 `Picker mode="time"`
6. **UI 文案禁敏感词**：`AI|大模型|GPT` 一律不出现（微信提审合规），用"智能推荐/小助手/帮我挑"替代（`constants/copy.ts` 集中管控 + grep 验收）
7. **功能入口宫格化**、筛选/操作要有即时可见反馈；列表限高内滑动 + 底部渐隐提示
8. 外部 API（天气/一言/GLM）失败必须静默降级，不阻塞主流程

本项目新增（账号/云时代）：

9. **数据权威在云端**（注册用户）：本地只是缓存与离线兜底；写入乐观更新 + 队列重试，断网可用、联网补传
10. **游客数据永不落库**：服务器为游客仅记身份与到访时间（统计用），业务数据全在本地沙盒，转正时由用户主动选择是否带走
11. **API Key 只存后端**：GLM Key 上云（旧版存用户端的 `aiKey` 域已删除）
12. **B 端为单管理员**：ADMIN_TOKEN 单口令进入，不做 B 端账号体系（5 人规模，克制即正义）

## 明确不做的事

- 刷题/题库（用户明确不要，延续）
- 深色模式（原则底线 4）
- 手机号注册、用户名密码（个人主体小程序无企业认证，拿不到手机号；openid 即账号）
- B 端多人/角色权限体系（单管理员足够）
- 用户端自定义任务（发放权在 B 端，原则底线 2）
- 微信云开发（数据锁死在腾讯、面试讲不出自有架构，明确排除）
- 旧 PWA 的"好友同步/配对码"机制（serverUrl+pairCode 已由账号体系+B 端彻底替代）
