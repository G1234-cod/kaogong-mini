# 07 · B 端管理后台

> 主理人专属的 Web 管理端，替代旧版 PWA 的"看板端（Observer.tsx）"角色。**已实现**：`admin/` 目录（Vue 3 + Vite + TS + vue-router + TailwindCSS + ECharts），四页齐备；接口契约见 [06](./06-后端API契约.md)。

## 定位与决策记录

| 决策 | 结论 | 理由 |
|------|------|------|
| 技术形态 | Vue 3 + Vite，构建产物为**纯静态文件**，Nginx `location /admin` 直接托管（与小程序后端同域，无需新增域名/证书） | 无 SSR、无 Node 常驻进程，运维零负担 |
| 账号体系 | **单管理员，不做登录注册**——首次输入 ADMIN_TOKEN 存 localStorage，之后每次请求带 `X-Admin-Token` 头 | 5 人规模下克制即正义；面试讲"资源匹配"反而是加分项 |
| 图表库 | **ECharts**（折线/热力/横条），指标条用 Tailwind 进度条 | 后台无包体压力，单依赖换全套图表能力 |
| 隐私口径 | **用户详情页展示全部数据明细（含账本金额、心情日记正文）** | 主理人明确否决"只看汇总不看明细"的遮蔽方案——用户群是亲友，B 端是主理人自用工具；提审《隐私政策》中写明数据用途即可 |
| 统计方式 | 打开看板时现场聚合（`GET /admin/stats` 服务端内存全量计算） | 用户量级小秒出，不建预聚合表；人多了再优化 |

### 2. 用户

- **列表**：昵称（B 端备注）/ 自填昵称 / 角色（正式｜游客 chip）/ 最后活跃 / 连续打卡 / 累计专注 / 目标考试；按最后活跃或连续打卡排序；搜索框过滤 openid/昵称
- **详情页**（点行进入）：该用户全量数据明细
  - 打卡热力图（复用其 checkins 渲染 GitHub 风格）+ 连续/最佳连击
  - 心情趋势 + 低落记录一览、专注时长图表、三件事完成情况、复习进度
  - 账本月度汇总 + 流水明细、笔记列表
  - 任务达成时间线（claimed/granted/used/兑换码——**核销时对照券面兑换码**）
  - 数据即 `GET /admin/users/{openid}/data` 的 user_data 各域现场渲染

### 3. 任务与发券

- **任务列表**：每行 = emoji+名称 / 条件（中文文案）/ 公开|隐藏 / 全员|N人指定 / 兑换方式 / 达成人数 / active 开关 / 编辑 / 下架
- **发布/编辑表单**：
  ```
  emoji[🎁▾]  名称[________]  说明[________]
  达成条件： [连续全勤 N 天▾]  参数[ __ ]
     （5 类下拉：连续全勤N天 / 累计全勤N天 / 周末双满勤 / 连续3天好心情 / 单日N个番茄）
  兑换方式： (●) 直接入袋  ( ) 生成兑换码
  可见性：  (●) 公开（显示进度）  ( ) 隐藏（达成才揭晓）
  发给：    (●) 全体用户  ( ) 指定用户：[多选框：从用户列表勾选]
                          [ 发布任务 ]
  ```
- **直接发券**：emoji + 券名 + 说明 + 选人（或全员）→ `POST /admin/grant`（逐人）；发放记录倒序流水
- 达成条件中文文案与 cond_type 映射见 [05](./05-任务与奖励体系.md) 条件表

### 4. 备份与数据

- **旧 PWA 导入**：粘贴导出 JSON → 选目标用户（须先完成"正式开始"注册）→ `POST /admin/import` → 展示导入域数量；操作前 confirm 提示"覆盖式导入"
- 用户数据手动导出（单用户 JSON 下载，应急找回）
- 显示服务数据概况：users/user_data 行数、data.db 文件大小、最近备份时间（备份 cron 见 [08](./08-部署与运维.md)）

## 统计指标口径（/admin/stats 明细）

| 分组 | 指标 | 口径 |
|------|------|------|
| 人气 | 总用户 / 今日活跃 / 近 7 日新增 / 游客转正率 / 次日留存 | 活跃 = 当日有 writeOps 或 snapshot 拉取的 openid 去重（含游客到访）；转正率 = role=user ÷ 全部到访 |
| 学习 | 打卡完成率 / 人均连续 / 专注日均 / 三件事完成率 / 复习完成率 | 完成率按当日应有打卡项数折算；复习完成率按到期闪卡已翻面数 |
| 备考 | 目标考试分布 / 平均倒计时 | 取各用户 exams 最早未过期考试 |
| 生活 | 平均喝水杯数 / 平均心情 | 全体当日 dayLogs.water 长度、moods 均值 |
| 发券 | 发出张数 / 已核销张数 | grants 表计数 + user_data.rewards 的 used 统计 |

## 实施要点（已落地）

- `admin/` 独立工程：`npm run dev`（vite proxy `/api` → `https://app.gyx-a.cn/api`，规避无 CORS）；`npm run build` 产 `dist/`，上传服务器 `/var/www/kaogong-admin/`
- nginx `location /admin/`（`server/deploy/kaogong-app.conf` 已含）：`alias` + `try_files` SPA 回退 `/admin/index.html`
- 鉴权：运行时口令输入（`src/App.vue`）→ localStorage `kg-admin-token` → 全请求带 `X-Admin-Token`；401/403 清口令并弹回输入框（`src/api.ts` 派发 `kg-admin-unauthorized` 事件）
- 全部接口复用 [06](./06-后端API契约.md) 的 /admin 组，**B 端不引入任何后端新表**；统计聚合在服务端做，B 端只渲染
- 文件结构：`src/api.ts`（fetch 封装+类型）+ `src/views/` 五件（Dashboard / Users / UserDetail / Tasks / Backup），vue-tsc 零错误
