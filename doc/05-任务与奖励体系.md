# 05 · 任务与奖励体系

> 本体系是产品的核心卖点，也是 B 端存在的主要理由。旧版 PWA 的"看板端发奖"（Observer + pairCode）演进为"B 端发任务+发券"；用户端（C 端）达成判定引擎沿用旧版前端实现。

## 概念模型：三件套

| 件 | 存哪 | 谁写 | 内容 |
|----|------|------|------|
| **任务定义** | 服务端 `tasks` 表 | B 端 CRUD（主理人） | 券名/emoji/说明/达成条件/公开或隐藏/兑换方式/作用范围 |
| **达成状态** | 用户端 `rewards` 域（随 user_data 上云） | C 端前端 | claimed/granted/code/used/achievedAt + 定义字段缓存 |
| **直接发券** | 服务端 `grants` 表 | B 端 | 不依赖任务达成的赠送券（奶茶券等），C 端增量拉取弹窗 |

设计要点：**定义权威在服务端，达成判定在用户端**（判定引擎需要 checkins/moods/pomodoroLogs 全量数据，且断网也能达成——沿用旧版架构决策 AD-3）；用户端把拉到的定义按 id 合并进本地 `rewards` 域后，状态更新走既有 writeOps 同步链路，**零新增写接口**。

## 任务定义字段（tasks 表，已建）

```python
id: str            # 'task-' + 随机；预设任务沿用旧 id（rw-milk-tea 等）
title / emoji / description
cond_type: str     # 5 类达成条件（见下表）
cond_param: int    # 条件参数（天数/个数；weekend_full 恒 0）
mode: str          # 'auto'=达成自动入袋 | 'code'=达成生成兑换码
hidden: bool       # 公开=显示条件与进度 | 隐藏=不显示详情，达成才揭晓
scope: str         # 'all'=全员 | 'users'=指定
target_openids: JSON数组  # scope='users' 时生效
active: bool       # 下架开关（软删）
created_at: int
```

## 5 类达成条件（B 端表单下拉选择，固定模板）

| cond_type | 语义 | cond_param | 用户端提示文案 |
|-----------|------|-----------|----------------|
| `streak` | 连续全勤天数达标 | N 天 | 「连续全勤打卡 N 天」 |
| `total_full` | 累计全勤天数达标 | N 天 | 「累计全勤 N 天」 |
| `weekend_full` | 最近一个完整周末（周六+周日）双满勤 | 0（忽略） | 「周末双满勤」 |
| `mood3` | 连续 3 天心情 ≥ 4 | 0（保留扩展天数） | 「连续 3 天好心情」 |
| `pomo_day` | 单日番茄钟个数达标 | N 个 | 「单日专注 N 个番茄」 |

**判定引擎（`pages/checkin` checkAchieve 改造）**：按 `cond_type` switch 判定，输入 RewardCtx（`allStreak / totalFullDays / mood3High / weekendFull / pomoToday`，各字段算法沿用旧版：全勤=每个顶层项完成（父子项感知）；今天没打不清零；心情从今天往回数缺记录跳过）。

⚠️ **修复旧版 bug**：旧版 checkAchieve 按**固定 4 个预设 id** 硬编码 switch，导致看板端自定义的隐藏任务（targetDays=0 且非预设 id）永不触发。新版按 cond_type 判定后，B 端发布的任何任务（含隐藏任务）均可正常触发——这是本轮改造必做项。

## 公开 / 隐藏

- **公开任务**：奖励卡显示名称/emoji/条件 + 进度条（streak 类可算 `min(100, allStreak/N*100)`；weekend_full/mood3/pomo_day 类显示条件文案，不显示百分比）；限高 4 条滑动
- **隐藏任务**：不显示详情，打卡页奖励卡底部常驻提示条「🎁 悄悄说：还有 N 个隐藏任务，达成条件才揭晓」（弹跳动画强调存在感）；达成瞬间 toast「🎉 解锁隐藏任务：xxx！」+ 盲盒弹窗揭晓券面

## 达成与兑付

- `mode:'auto'`（普通券）：达成即入奖券袋，券面直接可用
- `mode:'code'`（贵重券）：达成时前端 `genRedeemCode()` 生成 `KG-XXXX`（字符集去掉易混淆 I/O/0/1），券面显示兑换码，用户线下找主理人兑现；奖券袋点击核销置 used
- 兑换码幂等：已生成不覆盖（防重复达成刷新码）

## 作用范围：全员 + 可指定

- `scope:'all'`：全部用户可见可达成（统一激励，默认）
- `scope:'users'` + `target_openids`：仅指定用户可见（专属任务，如只给家人的）——B 端发布表单勾选用户多选框即得，`GET /tasks` 服务端按请求者 openid 过滤下发
- 下架语义沿用旧版"删除不传播"：`active=false` 后不再向**新用户**下发，已合并进用户端 rewards 域的任务保留状态与进度（防误删丢进度）

## 数据流全链路

```
B 端发布任务 ──POST /admin/tasks──▶ tasks 表
                                        │
C 端启动/前台 ◀──GET /tasks（全员+指向自己）─┘
        │ 按 id upsert 合并进本地 rewards 域（新定义补 claimed:false）→ writeOps 上云
        ▼
用户打卡 → rewardCtx 变化 → checkAchieve 命中 → 批量置 claimed/granted/achievedAt
        → （mode=code 生成兑换码）→ writeOps 上云 → 盲盒弹窗队列庆祝
        ▼
B 端看进度 = 读 user_data['rewards']（哪些用户达成/待发放/已核销，时间线）
        
B 端直接发券 ──POST /admin/grant──▶ grants 表 ──GET /grants?since=──▶ C 端增量拉取
        → 'grant-' 前缀追加进 rewards 域 → RewardPopup 弹窗 + toast「🎉 收到新券」
```

## 前端类型与迁移（types + normalize）

```ts
type CondType = 'streak' | 'total_full' | 'weekend_full' | 'mood3' | 'pomo_day'
interface TaskDef {
  id: string; title: string; emoji: string; desc: string
  condType: CondType; condParam: number; mode: 'auto' | 'code'; hidden: boolean
}
interface Reward {
  id: string; title: string; desc: string; emoji: string
  condType?: CondType; condParam?: number   // 无 = 非任务型（如 grant-* 券）
  hidden: boolean
  claimed: boolean; granted: boolean
  mode: 'auto' | 'code'; code?: string; used?: boolean; achievedAt?: number
}
```

normalize 迁移（`src/store/normalize.ts` condOf）：合法 condType 保留 → 4 个 rw-hidden-* 预设 id 按上表补 → 旧 `targetDays > 0` → `condType:'streak', condParam:targetDays` → 非任务型返回空条件；缺 desc 补 ''、emoji 补 🎁、mode 补 'auto'。

启动同步（`src/utils/rewards.ts` mergeServerRewards）：`Promise.all([fetchTasks(), fetchGrants()])` → tasks 按 id upsert 定义字段（保留 claimed/granted/used/code/achievedAt 本地状态）→ 未见过的 grant 以 `grant-` 前缀追加并 toast → changed 才写回上云；拉取失败静默沿用本地。

## 验收要点

- [ ] B 端发布公开任务（streak 5 天）→ 用户端奖励卡出现进度条，打卡推进
- [ ] B 端发布隐藏任务（pomo_day 3）→ 用户端不显示详情只见提示条 +1，打满 3 番茄触发盲盒+toast
- [ ] 指定用户任务：非目标用户拉不到、目标用户可达成
- [ ] mode=code 达成出码，重复触发不刷新码；奖券袋核销
- [ ] B 端发券 → 用户端下次打开 RewardPopup 弹窗（含多张排队）
- [ ] 全程断网：达成照常（本地），恢复联网后状态补传上云
